# Stock Screener V2 — Methodology (English)

## Purpose

Research-only EOD filter to select stocks for later analysis of T+3/T+5 trading.
A PASS is not a buy signal and does not imply historical or future profitability.

## Inputs and timing

Read only `stock_features` where `timeframe = 1d` on the explicitly requested
Vietnam trading date. These values are produced separately from `stock_daily`.
Scope is limited to currently active master symbols; missing exact-date data are
not substituted with previous-session data.

## Versioned scoring rules

All five rules are binary: earn the entire weight if true, otherwise zero.

| Rule | Condition | Weight | Research rationale |
| --- | --- | ---: | --- |
| Trend | `close > ema20 > ema50` | 40 | Prefer a rising short/intermediate trend |
| RSI | `50 <= rsi14 <= 70` | 15 | Prefer the provisional positive-momentum band |
| MACD | `macd_histogram > 0` | 20 | MACD line above its signal line |
| Volume | `volume_ratio >= 1` | 10 | Volume at least the 20-session average |
| Value | `value_ratio >= 1` | 15 | Traded value at least the 20-session average |

Score is the sum of earned weights (integer 0–100), NOT a probability.
PASS requires score >= 70 with all mandatory inputs present and valid;
otherwise FAIL. Any missing, non-finite, or invalid required input produces
NOT_EVALUABLE with a NULL score, never zero-filling unknown input.

There are no hard gates beyond data validity in V2. For example, a stock with
a failed trend rule could still PASS from other criteria if its score reaches
70. This distinction from V1 is intentional and subject to historical study.

## Why these weights?

The provisional allocation (40/15/20/10/15) emphasizes trend (40 points),
then MACD momentum (20 points), and uses RSI and activity ratios as supporting
evidence. These are **operator choices**, not statistically fitted coefficients
or assertions of causal effect. Volume and value may be correlated and should
not be interpreted as independent evidence.

## Data lineage and reproducibility

A source-controlled JSON config defines executable rules. This English document
and the matching Vietnamese document describe them for human review.
Both documents and the JSON contribute to a SHA-256 `config_hash` stored in
`screener_configs`, with the immutable `screener_version`. V2 result rows keep
that hash and detailed per-rule earned points. An edit to any rule, threshold,
weight, or methodology requires a new version; never mutate the previous version.

## Limitations and future testing

The filter has not been proven profitable. Before interpreting historical
results, validate raw/clean/feature completeness, date availability,
chronological sampling, entry/exit assumptions, fees/slippage, baseline,
sample size, and uncertainty. Backtests must run separately and attach their
own versioned methodology; Screener never triggers them.
